`AttentionManager.reassign_overlaps(agents, available_tasks, threshold=0.05)` compares actual Poincare positions, preserves the first region in stable agent-ID order, and proposes moving redundant workers only to real, unclaimed backlog tasks. Backlog order sets priority; the new hierarchy-derived position must clear every other current region. No suitable task produces no move. The helper leaves inputs, budgets, independence barriers, and durable records untouched. The coordinator must validate and commit proposals, update worker anchors, and explicitly communicate task changes. Structural overlap does not establish duplicate reasoning or semantic equivalence.

`ControlledNovelty().select_probe(eventid, distance, verified, interval=10)` returns a deterministic `diversity_probe` decision: a candidate must be verified by the caller, at least 1.5 Poincare units away, at least ten unique observations after the previous selection, and within a default global lifetime cap of three selections. Repeated IDs replay the same decision without consuming quota. Persist `snapshot()` with the event's routing decision before dispatch, then reconstruct `ControlledNovelty(saved_state)` using the same constructor settings. A returned `True` on replay is an idempotent decision, not authorization to deliver twice. The existing router still limits a probe to one additional eligible recipient and checks its attention budget; mandatory delivery is unaffected. This scheduler certifies neither the verification flag nor the value of a distant claim. Its history is bounded at 10,000 unique events by default; reaching that limit requires an explicit new scheduling epoch rather than an automatic reset. Helpers perform no model calls or storage/network operations.

The coordinator's `assign_task` commits its requested task and assignment intent in one SQLite transaction, updates the index anchor, and sends a bounded task-assignment steer when the worker has an active turn. Receipts distinguish `accepted`, `refused`, `uncertain`, and `no_active_turn`; every receipt retains `worker_adoption_verified: false`. Replaying an assignment ID returns the recorded receipt without another steer. An interrupted intent lacking a receipt stays uncertain. `initialize_index` restores committed worker tasks and rebuilds their anchors; this repairs the host projection and does not prove that a remote worker adopted an assignment. `rebalance_attention` uses the real backlog through that same assignment path. The novelty scheduler uses distances to peers, excluding the author, and its state is committed with routing decisions. Replaying a routed event leaves its novelty quota and addressed deliveries unchanged.

Transport metadata revision `explicit_inbox_ack_v1` distinguishes receipt-bearing events from optional context by the coordinator's registered `expected_codes`, independently of mandatory routing. Known-code events carry `requires_ack: true` and tell the worker to call `await_peer_findings` before acknowledging the exact IDs and codes returned by that inbox. Optional coordinator probes carry `requires_ack: false` and `context_kind: optional_context`; they do not belong in the two required peer receipts. Both messages say that steer acceptance does not establish reading. This corrects the earlier universal ACK instruction, which was impossible to follow for optional probes lacking a receipt code or inbox delivery. Routing scores, fixture constraints, and ACK validation are unchanged; comparisons across runs should record the transport metadata revision.
